## Task 1 fixed conventions (P1, P2, Q1, Q2, 2:4) — recorded 2026-11-25 BEFORE any of these conditions ran

### Pruning (P1 magnitude, P2 Wanda)
- Per output row of every eligible matrix zero exactly k = s * d_in weights (s in {0.25, 0.50, 0.75}; d_in in {1536, 8960} so k is an exact integer; asserted).
- Lowest scores pruned; ties broken by column index (stable ascending sort: among equal scores the lower column index is pruned first).
- Scores: magnitude S = |W_ij|; Wanda S = |W_ij| * ||X_j||_2 with ||X_j||_2 = sqrt(sumsq_j) from `results/task1/baseline/calib_input_stats.npz` (all 128 x 512 calibration tokens, FP32 accumulation).
- Pristine FP16 weights restored (and verified bit-exact) before every condition.
- Reported separately: mask-pruned fraction (by construction) and actual zero fraction (baseline already has 2,914 exact zeros).
- 2:4 diagnostic: Wanda scores; each row split into groups of 4 contiguous input columns; keep the 2 highest, zero the 2 lowest (ties by column index); compared with unstructured 50% Wanda; equal zero counts from the masks asserted. Storage: bitmask-sparse16 formula and a 2:4 representation estimate (FP16 kept values + 2-bit position index per kept value). No sparse-tensor-core speedup claimed (T4).

### Quantization (Q1 uniform, Q2 AWQ-style; identical quantizer later for Q3)
- Weight-only, asymmetric, group size 128 of contiguous input columns within each output row. Zero-padding of the last group (padded entries excluded from min/max) is implemented but asserted unused (d_in divisible by 128).
- Per group: w_min, w_max; s = (w_max - w_min)/(2^b - 1) in FP32, then s := max(s, 2^-24) (smallest positive FP16; covers w_max == w_min) and rounded to FP16 (the stored value); every later use of s uses this FP16 value.
- z = clamp(round(-w_min / s), 0, 2^b - 1) (integer zero-point).
- w_hat = s * (clip(round(w/s) + z, 0, 2^b - 1) - z) (the PDF quantizer), computed in FP32 from the FP16 s and cast to FP16.
- Rounding: torch.round (round-half-to-even).
- Serialized per group: b-bit zero-point, 16-bit FP16 scale, 128 b-bit codes => 128b + b + 16 bits per group. Layout: per matrix ONE little-endian bitstream, row-major over (row, group), each group as [zero-point][scale][codes], each field LSB first; the matrix bitstream is padded to a whole byte. A real packer/unpacker is used; serialized length must equal the storage formula and unpack(pack) must reproduce the dequantized FP16 tensor bit-exactly (checked for every matrix in every quantized condition).
- Evaluation uses dequantized FP16 weights ("fake-quantized FP16"); latency is dense FP16 execution, not low-bit execution.

### Q2 AWQ-style scaling
- Scale groups per block, inputs captured from the UNCHANGED FP16 model one block at a time over all 128 x 512 calibration tokens: (1) q/k/v (input_layernorm output), (2) o_proj (attention output), (3) gate/up (post_attention_layernorm output), (4) down_proj (act(gate)*up).
- Per input channel: s = clamp(mean_t |x_tj|^alpha, min 1e-4), normalised by sqrt(max(s)*min(s)) (llm-awq `auto_scale` formula); scales rounded to FP16.
- Grid: alpha in {0, 0.05, ..., 0.95} (20 values). alpha = 0 gives s = 1, i.e. exactly Q1.
- Objective: MSE of the scale group's projection outputs (all projections of the group concatenated, no bias) between W X and [Q(W diag(s)) diag(1/s)] X on all calibration tokens; argmin over the grid (ties -> smaller alpha). One search per bit width; the captured activations are shared by the three bit widths. Note: llm-awq inspects the self_attn / mlp module outputs for q/k/v and gate/up; we use the projection outputs as specified by the reviewer.
- Inverse-scale compensation: down_proj scales are folded into up_proj's output rows (W_up <- diag(1/s) W_up) BEFORE up_proj is scaled/quantized (order: all four scale vectors are searched on the original block weights, then folded/applied, then quantized, as in llm-awq). o_proj <- v_proj folding is invalid under GQA (v_proj out 256 != o_proj in 1536) -> o_proj scales serialized. q/k/v and gate/up follow RMSNorm (not a linear projection) -> FP16 scales serialized (not folded into norm weights). Serialized scale bytes count toward Q2 storage. In the fake-quant evaluation each serialized compensation is merged into the dequantized weight (W_eff = Q(W diag(s)) diag(1/s), FP32 then FP16).
- Verified before rounding: rescaled-but-unquantized model (scaled weights, down->up folding, explicit runtime division of inputs for serialized groups) vs baseline logits on 4 calibration sequences (max abs logit diff reported).
- Reproduced from published AWQ: activation-aware per-channel scale search over a recorded grid, scale folding into the preceding linear layer where valid. NOT reproduced: AWQ weight-clipping search (would change the shared quantizer), fused INT4 kernels / inference engine, AWQ's module-output objective for q/k/v and gate/up.

## P3-design — pre-registered 2026-11-26, committed BEFORE the P3 kernel; applied automatically (no human sees test results in between)
- Unit: Transformer block (28 units); all 7 eligible projections of block l get sparsity s_l. Inside each projection the P2 rule is unchanged: Wanda scores |W_ij|*||X_j||_2 from `results/task1/baseline/calib_input_stats.npz`, per-output-row lowest-k masking, stable sort (lower column index pruned first on ties).
- Sensitivity (OWL, Yin et al. 2024): for each projection count entries with Wanda score > M * mean(that projection's Wanda scores); D_l = (sum of counts over the block's 7 projections) / (eligible params in block l).
- Allocation: s_raw_l = S + lambda - 2*lambda*(D_l - min D)/(max D - min D) (if max D == min D: s_raw_l = S); final s_l = clip(s_raw_l + c, 0.10, 0.85) where the constant c is found by bisection (200 iterations on [-1, 1]) so that the parameter-weighted mean of s_l equals S (all blocks have identical parameter counts).
- Integer rounding: per projection k = round(s_l * d_in) (Python round, half-to-even) zeros in every row; Delta = (P2 zero count at S = S * #eligible params) - sum(k * rows). Rows are then adjusted by sign(Delta) (one each) in the order block index ascending, projection order (q,k,v,o,gate,up,down), row index ascending, until Delta = 0. Exact equality with the P2 count is asserted. Final s_l and exact per-block zero counts are stored.
- Selection data: ONLY the 32-sequence C4 development manifest (`c4_development_locked`), each 512-token sequence scored as one window (targets 1..511, 16,352 tokens), with the harness PPL code. Grid M in {3,5,7,10} x lambda in {0.02,0.05,0.08,0.12,0.16,0.20}, selected separately for S = 0.50 and S = 0.75 by lowest dev PPL; ties -> smaller lambda, then smaller M. lambda = 0 (uniform = P2) is evaluated on dev as a reference and is NOT selectable. The full grid is saved (`results/task1/p3_selection.json`) as the record of unselected designs.
- Test evaluation: P3 at S = 0.50 (both PPL suites + full HellaSwag 2,000) and S = 0.75 (both PPL suites + first-512 diagnostic), with the same storage/output-error/timing code as every other condition.
- Limitation: OWL ratios and the allocation ignore interactions between pruned blocks.

## Q3-design — pre-registered 2026-11-26, committed BEFORE the Q3 kernel; applied automatically
- Quantizer identical to Q2: AWQ-style per-channel scales (same grid, objective, folding, serialized FP16 scales) + the Q1 group-128 asymmetric quantizer. Only bit widths change. Unit: block (all 7 projections share b_l); b in {2,3,4,8}.
- b = 2 needs new AWQ scales: the search is re-run in this kernel for b in {8,4,3,2} with the same grid, calibration activations and objective. The re-derived chosen alpha indices for b in {8,4,3} are compared with `results/task1/q2_awq_search.npz` and the match is asserted/recorded; Q3 always uses the SAVED Q2 scales for b in {3,4,8} (so Q3 is bit-identical to Q2 for any block at those widths) and the new search's scales for b = 2.
- Sensitivity probe: for each block l and b in {2,3,4,8}, quantize ONLY block l at b (rest FP16) and measure dev NLL on the 32-sequence C4 dev manifest (same windows as P3). dNLL(l,b) = devNLL - devNLL_FP16. 112 probes; full matrix and probe time saved.
- Budgets (total packed bytes incl. eligible codes, zero-points, FP16 group scales, serialized AWQ scales and all uncompressed parameters with tied counted once): B4 = 1,147,982,848 B (Q2 uniform INT4), B3 = 982,928,896 B (Q2 uniform INT3).
- Allocation: minimise sum_l dNLL(l, b_l) s.t. total packed bytes <= budget, using the exact per-block packed-byte function (+ serialized AWQ scale bytes, independent of b). Solved exactly by DP over blocks with integer byte states. Ties: lower objective, then fewer bytes, then the lexicographically larger bit vector (higher bits to lower block indices).
- Additivity assumption: isolated per-block probes ignore cross-block interaction; the sum of probe dNLLs is a prediction, checked by evaluating each chosen allocation on dev (predicted vs realised dev dNLL).
- Test evaluation: Q3@B4 and Q3@B3, both PPL suites + full HellaSwag 2,000 + storage (actual packing, realised bytes <= budget asserted) + output error + timing.

## Task 2 Parts A/B conventions — recorded 2026-11-26 BEFORE the Task 2 kernel
### Part A
- Tensors: q, k, v and the backward seed dO drawn as N(0,1) in FP32 on CUDA with torch.Generator seed 6304 + L, then cast to FP16 for the FP16 runs (same values up to rounding). B=2, H=4, d=64, scale 1/sqrt(d).
- Reference: exact dense causal attention in FP32 computed in query chunks of 1024 (outputs and dQ/dK/dV by accumulated autograd), so a reference exists at every L; FP16 inputs are upcast.
- Dense operator: explicit QK^T, causal (+ optional key-padding) mask, max-subtracted softmax, PV, all in the input dtype. Fully-masked rows (no admissible key) return 0 and receive zero gradients.
- Tiled operator: query and key tiles of equal size (64/128/256), PDF online-softmax update with FP32 accumulators m, l, o (scores upcast to FP32), output cast to the input dtype; autograd through the Python loop stores per-tile intermediates (reported; not FlashAttention).
- SDPA: is_causal=True; dispatched backend recorded via torch._fused_sdp_choice and profiler kernel names; each backend forced with sdpa_kernel and recorded supported/unsupported per dtype/L.
- Timing: 3 warmup + 10 timed reps, CUDA events; forward-only (no_grad) and forward+backward separate; OOM/unsupported are rows. cuda:1 idle. MQAR stream generation runs concurrently on CPU cores 1..n-1 while Part A is pinned to core 0 (CPU contention possible; recorded).
### Part B
- Training-stream rule: for (K, regime, seed), example i of update u is make_example('train', K, regime, (seed-6304)*10^7 + u*32 + i); identical across architectures, disjoint across seeds. Streams are generated once and cached; frozen dev (256/cell) and test (1,024/cell) files used as supplied; course invariant checks (validate on every frozen record, regeneration equality, train spot checks) run first and saved.
- Model: 2 pre-norm blocks, d_model 128, 4 heads x 32, MLP 128->512->128 with exact (erf) GELU, nn.LayerNorm (eps 1e-5) pre-attention, pre-MLP and final, learned token embeddings (vocab 256), fixed sinusoidal positional embeddings (base 10000), q/k/v and output projections with bias. Identical parameters (437,824) for every operator.
- Output head (choice): a 64-way linear classifier over value IDs 128..191 applied ONLY at the marked query positions; cross-entropy against (answer_id - 128), mean over all supervised queries in the batch; every other position is masked (query-position classification, not next-token LM). Label-space chance 1/64; 1/K random-choice baseline also reported.
- Operators: dense = SDPA is_causal; window W=64 = j in [i-63, i]; mixed local/dilated = heads 0-1 local [i-63, i], heads 2-3 j = i - o, o in {0,4,...,252}, j >= 0; window and dilated use an EXPLICIT dense boolean mask [H,T,T] passed to SDPA (correctness implementation; its storage is not an efficient sparse kernel); linear = phi(x) = ELU(x)+1, a_t = phi(q_t)^T S_t / (phi(q_t)^T z_t + eps), eps = 1e-6, trained with the cumulative-sum form which MATERIALISES prefix tensors [B,H,T,32,32]; the O(1)-state recurrence is used in the inference sweep and tested equal.
- Protocol: AdamW (betas 0.9/0.999, eps 1e-8, weight decay 0.01 applied to all parameters, identical across operators), peak LR 8e-4, batch 32, 4,500 updates, LR(u) = 8e-4*(u+1)/200 for u < 200, then linear decay from 8e-4 at u=200 to 0.15*8e-4 at u=4500; global-norm clip 1.0; FP32; seeds 6304/6305/6306 (torch.manual_seed(seed) before model init). Train loss logged as the mean over every 25 updates; dev accuracy on all 9 dev cells at updates 500/1000/1500/2000/3000/4500.
- Evaluation: final checkpoint on all 9 frozen test cells; accuracy over supervised queries; distance = query position - saved source position (asserted equal to the generator's saved distance); bins [0,32),[32,64),[64,128),[128,256). Mask control: each dense mixed K=16 model re-evaluated with the W=64 mask imposed at test time only.
- Packing: several training processes may share a GPU if a measured probe shows >= 1.15x aggregate throughput; training step times under packing are not clean timings. Clean per-architecture train-step timing and the forward-only inference sweep (T in {256,1024,4096,8192}, B=4, FP32, 10 warmed reps) run exclusively at the end.
- Architectural access limit: two stacked W=64 layers reach at most 2(W-1) = 126 positions back, so far-regime queries (distance >= 128) are outside the window model's receptive field by construction.

## Q3-proj design (second Q3 design) — pre-registered 2026-11-26, committed BEFORE the Q3-proj kernel; applied automatically
- Why a second design: the block-level Q3 design gave a uniform allocation at both budgets (all 28 blocks cost the same bytes and the bit menu {2,3,4,8} is coarse). That design is RETAINED and reported as an unsuccessful design (PDF Step 9 / What to Watch For). The second design changes ONLY the allocation unit.
- Unit: each eligible projection (28 blocks x {q,k,v,o,gate,up,down} = 196 units); b_u in {2,3,4,8}. Quantizer identical to Q2: AWQ-style scales with the same grid/objective/calibration activations, Q1 group-128 asymmetric quantizer. Scales for b in {3,4,8} = `results/task1/q2_awq_search.npz`, for b = 2 = `results/task1/q3_awq_search.npz`. In this kernel the search is re-run for b in {8,4,3,2} (split over the two GPUs) and the chosen alpha indices and FP16 scales are ASSERTED equal to the saved npz files before any probe result is used.
- Mixed bits inside one AWQ scale group: each projection uses the scale vector of its own bit width for its scale group (qkv / o / gateup / down). down_proj scales are folded into up_proj rows only when down_proj is quantized, using down's bit width (up_folded = W_up / s_down(b_down); then up is quantized with the gateup scale of b_up). Serialized FP16 scale bytes per (block, serialized group qkv / o / gateup) = (number of DISTINCT scale vectors used by the group's projections) x d_in x 2 bytes; down scales are folded and cost no bytes.
- Sensitivity: isolated dev dNLL(u, b) on the 32-sequence C4 dev manifest (same windows/code as P3/Q3): quantize ONLY projection u at b, everything else FP16 (a down_proj probe also stores up_proj = W_up / s_down in FP16, i.e. the deployed fold); dNLL = devNLL - devNLL(FP16 of the same process). 784 probes, split by block over the two GPUs (blocks 0-14 cuda:0, 15-27 cuda:1); each GPU uses its own FP16 reference. Full 196 x 4 matrix saved.
- Allocation: exact multiple-choice knapsack, minimise sum_u dNLL(u, b_u) subject to total packed bytes <= budget, B4 = 1,147,982,848 B and B3 = 982,928,896 B. Total = sum_u quantized_matrix_bytes(u, b_u) (storage.py convention = the real packer length) + serialized AWQ scale bytes (rule above) + every uncompressed parameter (tied counted once). Solved with scipy.optimize.milp (HiGHS): binary one-hot x[u,b], binary y[l,g,v] per distinct scale vector v of serialized group g in block l with x[u,b] <= y[l,g,v(b)]; objective in micro-nats (x 1e6) so HiGHS's absolute gap is negligible, mip_rel_gap = 0. Ties: a second MILP minimises total bytes subject to objective <= optimum + 1e-6 micro-nats. Realised integer bytes are recomputed and asserted <= budget. Optimality of the MILP formulation verified against brute force on small instances in tests.
- Additivity assumption: isolated per-projection probes ignore interactions (including the down->up fold); the sum is a prediction checked on dev (predicted vs realised dev dNLL of each chosen allocation).
- PRIMARY Q3 (dev-only, decided before any test number of Q3-proj exists): at each budget the primary Q3 is the design with the LOWER REALISED dev NLL among {block-level (= its chosen allocation, re-measured on dev in this kernel), projection-level}; ties -> block-level. Both designs are reported in full regardless.
- Test evaluation: Q3-proj@B4 and @B3 (conditions `q3proj_b4`, `q3proj_b3`): both PPL suites + full HellaSwag 2,000 + output error + storage with actual packing (realised packed bytes <= budget asserted); predicted vs realised dev dNLL; exclusive ABBA timing (short: baseline, q3proj_b4, q3proj_b3 with baseline references), written to `results/task1/retiming_q3proj.json`.
- Summary/diagnostics: Q3(primary)-Q2 and Q3-proj-Q2 paired bootstrap CIs at both budgets; 196 x 4 sensitivity matrix and both bit maps saved for plotting.

## Task 2 B3 intervention: reachable-query curriculum — pre-registered 2026-11-26, BEFORE the B3 kernel
- Motivation: the window W=64 model trained on mixed K=16 failed to learn even reachable near queries (test near 0.069; dev ~0.04 throughout). The same architecture trained near-only reaches 1.00. Hypothesis: unreachable queries (most of the mixed regime lies beyond the 126-position receptive field) act as label noise that prevents learning the reachable associations.
- Intervention: a curriculum changing the ratio of reachable to unreachable queries. Same window W=64 architecture, same parameter count (437,824; 0 extra parameters, 0 extra persistent state, same 64 attended positions per query), same optimizer, LR schedule, 4,500 updates, batch 32, clipping, seeds. Only the per-example training distribution changes:
  - updates 0-1,499: 100% near-regime K=16 examples;
  - updates 1,500-2,999: example (u, i) is mixed-regime with probability p(u) = (u - 1500) / 1500 (linear 0 -> ~1), otherwise near;
  - updates 3,000-4,499: 100% mixed-regime.
  - Regime draw: r = numpy.random.default_rng(seed).random((4500, 32)); example (u, i) is mixed iff r[u, i] < p(u). The example itself is make_example('train', 16, regime, (seed - 6304) * 10^7 + u * 32 + i), i.e. element (u, i) of the SAME near / mixed K=16 training streams used in B1 (seed-specific index ranges). The 4,500 x 32 regime mask is saved with each run (exact record of the examples used).
- Comparator: window K=16 mixed (B1), seeds 6304/6305/6306. Run names `window_K16_curriculum_s{seed}`.
- Development-selection rule: none. The schedule is fixed a priori and not tuned; dev is used only for the checkpoint curves (all 9 dev cells at 500/1000/1500/2000/3000/4500).
- Reachable fractions of the mixed K=16 TEST cell (computed now from the supplied test distances only, before training; 16,384 queries): distance <= 126 (key and value tokens inside the two-layer receptive field): 0.4929; distance <= 64 (value token q-1 back at most 63, i.e. attendable directly by the second layer after the first layer binds key -> value; the near-regime mechanism): 0.2126. Near K=16 test cell: all distances <= 63; far K=16: all >= 128.
- Prediction (written before evaluation): near-regime test accuracy rises to >= 0.9 (vs 0.069); far stays near 1/64 (architectural limit); mixed accuracy approaches the fraction of reachable queries: 0.4929 (+ chance 1/64 on the rest = 0.501) if all receptive-field-reachable queries are solved, 0.2126 (+ chance = 0.225) if only the directly attendable ones are.
- Evaluation: all 9 test cells, distance bins, curves, parameter count, query outputs, exactly as the other Part B runs.

## Task 2 Part C conventions — recorded 2026-11-26 BEFORE any Part C GPU run (fixed a priori; no tuning, no dev prompts)
- Model/format: Qwen/Qwen2.5-1.5B-Instruct @ 989aa7980e4cf806f80c7fef2b1adb7bc71aa306, FP16, SDPA. Prompt = tokenizer.apply_chat_template([{"role": "user", "content": user_text}], add_generation_prompt=True) with the template's default system prompt (same as Task 3). No BOS added (Qwen2).
- Split rule: every user_text ends with "\nQUESTION_BEGIN\n" + "What is the access code for CASE-<...>? Reply with only five digits." (regex asserted for all 180; exactly one marker). CONTEXT = all tokens before the first token of the question text ("QUESTION_BEGIN\n" stays in the context); SUFFIX = question tokens + "<|im_end|>\n<|im_start|>assistant\n" (30-31 tokens). Defined on token IDs of the full sequence (first token whose start offset >= the question's start); verified for all 180 prompts that no token straddles the boundary and that tokenizing context and suffix separately gives the identical sequence. Encoded context lengths: 2,608-2,652 (nominal 2,048) and 5,196-5,246 (nominal 4,096); per-prompt lengths in results/task2/partC/lengths.json.
- Generation: greedy = argmax of the logits (no repetition penalty, no sampling; the Instruct generation_config's do_sample/temperature/top_p/top_k/repetition_penalty=1.1 are NOT used), max_new_tokens = 16, stop on any EOS id of generation_config ([151645 <|im_end|>, 151643 <|endoftext|>]).
- Answer extractor: the first maximal run of exactly five consecutive digits in the decoded output (regex (?<!\d)\d{5}(?!\d), special tokens skipped), else "no answer". Exact match = extracted == gold code.
- Reference-answer NLL: teacher-forced sum of NLLs of the gold code tokens (5 single-digit tokens) + <|im_end|> after the suffix, fed token by token with the same cache semantics as decoding.
- Post-prefill KL: KL(p_FP16 || p_method) over the full vocabulary (FP32 log-softmax) of the first answer-token distribution (logits at the last suffix position).
- Cache mechanics: retained keys are post-RoPE and never re-rotated; appended tokens use the ORIGINAL absolute position_ids (L, L+1, ...); cache_position = physical positions (P, P+1, ...) and a 2D all-ones attention mask of length P+n (see atml4/task2/kv/kvcache.py for how transformers 4.57.1 consumes them).
- Budget: M_4(L) (channel-K/token-V INT4 reference) at the pre-question context length L; M_16(L) = 4 n_l H_kv d_h L; n_l, H_kv, d_h read from the config.
- Quantizer: Task 1's asymmetric form with group 64: s = max((max-min)/(2^b-1), 2^-24) in FP16, z = clamp(round(-min/s)), q = clamp(round(x/s)+z), x_hat = s(q-z) (round half to even); metadata per group = FP16 scale + FP16 offset field holding the integer zero-point z. Quantized entries are dequantized to FP16 and used with ordinary SDPA (packed storage != allocated memory). Codes packed little-endian within bytes; serialization = raw concatenation, no header (shapes implied by config + L + method).
- INT4 layouts (C3): token-wise K and V vs channel-wise K / token-wise V; the complete-64-token prefix (floor(L/64)*64 tokens) is quantized, the trailing L mod 64 tokens stay FP16; appended tokens (context residual + suffix + generated) stay FP16 until 64 uncompressed tokens accumulate, then that group is quantized in place (same layout).
- Eviction (C2): ONE global retained token set shared by all layers and heads; bytes = 4 n_l H_kv d_h n + 2n (uint16 indices stored once); n = the largest integer within M_4(L); always includes 8 sinks + 64 most recent. (i) sink+recent fills with the most recent remaining positions; (ii) question-aware fills with the highest-scoring positions (ties -> lower position). Appended tokens FP16.
- Question-aware score (simplified SnapKV-inspired, Li et al. 2024; not the published head-specific algorithm): suffix run by the working SDPA model on the full FP16 context cache; q_proj outputs captured by hooks, RoPE at absolute suffix positions, masked FP32 softmax over the rotary-positioned cached keys (context + causal suffix), GQA head h -> KV head h // (H/H_kv); mean over suffix positions and query heads, then mean over layers; context columns ranked. Scoring cost = that suffix forward + FP32 scoring; the suffix is then re-run on the compressed cache like every policy.
- Hybrid (C4): FP16 set = 8 sinks + 64 recent + top question-aware extras (one global set, uint16 indices); complement in sorted position order = INT2 channel-K (64 consecutive complement tokens per channel group) / token-V (64 features per token), complete 64-token groups only; the LAST (n_low mod 64) complement positions are FP16 without indices (derivable). Size f of the FP16 set = the largest f in [72, L] whose exact bytes fit M_4(L), found by exhaustive search. Appended tokens FP16 (shared decode component).
- Evidence retained: fraction of gold-evidence tokens (char span mapped through the offset mapping; EVALUATION ONLY) inside the FP16-retained selection (eviction: kept set; hybrid: selected FP16 set; the FP16 residual is reported separately).
- Shared decode component = FP16 bytes of the appended suffix + generated entries, reported separately; total live = method's context bytes + appended entries at the end of decoding (INT4 layouts: running groups).
- Accuracy: unconditional over all 180 prompts and conditional on FP16-reference correctness; no example is dropped. Paired bootstrap 2,000 resamples over prompts, seed 6304. The 10-prompt cells are descriptive.
